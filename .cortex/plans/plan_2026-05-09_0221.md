# Ontology Knowledge Graph — RAI on SPCS (Shareable)

## Context

The existing demo has 6 source systems (SAP, Oracle, Salesforce, FHIR, Workday, ServiceNow), a philosophical ontology framework in `ontology/`, a Streamlit app querying `DCA_DEMO`, and a marketplace sharing pattern in `sql/10_marketplace.sql`. A previous plan outlined a "Governance Brain" RAI pattern but no code exists yet.

The build creates a **node/edge knowledge graph** via the **RelationalAI Native App** on SPCS. It combines:
- **Metadata layer** — Snowflake objects (tables, columns, tags, policies, roles, shares) as nodes; ownership/tagging/lineage/access as edges
- **Business entity layer** — cross-system entities (Customer, Patient, Product, Employee, Organization, Incident, Order) as nodes; relationships (purchases, treated_by, assigned_to, owns) as edges

The graph is shareable via both a **Snowflake Share/Listing** (the materialized node/edge tables) and an **SPCS service endpoint** (RAI engine for live graph queries).

## Implementation Steps

### Step 1: SPCS & RAI Infrastructure (`sql/11_rai_setup.sql`)

- Create compute pool (`RAI_COMPUTE_POOL`, CPU_X64_S, 1 node)
- Create image repository for any custom sidecar containers
- Install RAI Native App from Marketplace (or reference it)
- Create RAI engine via `CALL RAI.API.CREATE_ENGINE(...)`
- Create a schema `GOVERNANCE.ONTOLOGY_GRAPH` to hold materialized node/edge tables
- Create roles: `ONTOLOGY_ADMIN` (manages graph), `ONTOLOGY_CONSUMER` (queries graph/endpoint)

### Step 2: Node/Edge Table Schema (`sql/12_ontology_graph_tables.sql`)

Materialized tables that RAI populates and that are also shareable:

```sql
-- NODES: unified entity table
GOVERNANCE.ONTOLOGY_GRAPH.NODES (
    node_id         VARCHAR PRIMARY KEY,
    node_type       VARCHAR,       -- TABLE, COLUMN, TAG, ROLE, POLICY, SHARE,
                                   -- CUSTOMER, PATIENT, PRODUCT, EMPLOYEE, ORG, INCIDENT, ORDER
    layer           VARCHAR,       -- METADATA | BUSINESS
    source_system   VARCHAR,       -- SNOWFLAKE | SAP | ORACLE | SALESFORCE | FHIR | WORKDAY | SERVICENOW
    fqn             VARCHAR,       -- Fully qualified name (metadata) or source ID (business)
    display_name    VARCHAR,
    properties      VARIANT,       -- JSON bag of type-specific attributes
    created_at      TIMESTAMP_NTZ
)

-- EDGES: relationships
GOVERNANCE.ONTOLOGY_GRAPH.EDGES (
    edge_id         VARCHAR PRIMARY KEY,
    source_node_id  VARCHAR REFERENCES NODES,
    target_node_id  VARCHAR REFERENCES NODES,
    edge_type       VARCHAR,       -- OWNS, TAGGED_WITH, MASKED_BY, LINEAGE_FROM,
                                   -- GRANTED_TO, PURCHASES, TREATED_BY, WORKS_FOR, etc.
    layer           VARCHAR,       -- METADATA | BUSINESS | CROSS (links metadata↔business)
    weight          FLOAT,         -- optional edge weight / confidence
    properties      VARIANT,
    created_at      TIMESTAMP_NTZ
)

-- GRAPH_SNAPSHOTS: audit trail
GOVERNANCE.ONTOLOGY_GRAPH.GRAPH_SNAPSHOTS (
    snapshot_id     INTEGER AUTOINCREMENT,
    snapshot_time   TIMESTAMP_NTZ,
    node_count      INTEGER,
    edge_count      INTEGER,
    metadata        VARIANT
)
```

### Step 3: RAI Rel Model (`python/rai_models/ontology_graph.rel`)

Rel source defining:
- **Entity types** as base relations (`:node`, `:edge`)
- **Integrity constraints** — every edge references valid nodes
- **Inference rules:**
  - `inferred_pii_propagation` — if a column receives data from a PII-tagged upstream column, infer it should also be tagged
  - `ownership_gap` — tables in SEMANTIC schemas with no `data_contract_owner` tag
  - `entity_resolution` — cross-system entity matching using name/email similarity (Jaccard on tokens)
  - `lineage_path` — transitive closure of LINEAGE_FROM edges
  - `governance_score` — composite score per node based on tag coverage, contract, ownership, quality monitoring
- **Graph algorithms:**
  - Connected components (for entity clusters)
  - PageRank (for identifying critical hub nodes)
  - Shortest path (for lineage tracing)

### Step 4: Graph Population Procedures (`sql/13_ontology_graph_populate.sql`)

Stored procedures that read from INFORMATION_SCHEMA, TAG_REFERENCES, ACCESS_HISTORY, and curated source tables to populate the node/edge tables:

1. `SP_POPULATE_METADATA_NODES()` — reads `INFORMATION_SCHEMA.TABLES`, `COLUMNS`, `TAG_REFERENCES`, `SHOW ROLES`, `SHOW GRANTS` → writes METADATA-layer nodes
2. `SP_POPULATE_METADATA_EDGES()` — builds ownership, tagging, masking, lineage, grant edges
3. `SP_POPULATE_BUSINESS_NODES()` — reads from curated source tables (e.g., `CURATED_DEV.SALESFORCE.DIM_ACCOUNT`, `CURATED_DEV.FHIR.DIM_PATIENT`) → writes BUSINESS-layer nodes
4. `SP_POPULATE_BUSINESS_EDGES()` — builds cross-entity relationships (customer→order, patient→encounter, employee→org)
5. `SP_POPULATE_CROSS_EDGES()` — links business entities to their metadata representations (Customer node ↔ CURATED.CUSTOMERS table node)
6. `SP_REFRESH_GRAPH()` — orchestrator that calls all above + records a snapshot

### Step 5: RAI Integration Procedures (`sql/14_rai_graph_sync.sql`)

- `SP_SYNC_TO_RAI()` — streams node/edge tables into the RAI model
- `SP_RUN_INFERENCE()` — executes Rel rules, writes results back to Snowflake tables:
  - `GOVERNANCE.ONTOLOGY_GRAPH.RAI_RECOMMENDATIONS` (governance gaps, inferred classifications)
  - `GOVERNANCE.ONTOLOGY_GRAPH.RAI_ENTITY_CLUSTERS` (resolved entities across systems)
  - `GOVERNANCE.ONTOLOGY_GRAPH.RAI_GOVERNANCE_SCORES` (per-node scores)
- `SP_APPLY_RECOMMENDATIONS()` — optional: takes approved RAI recommendations and applies tags/policies

### Step 6: SPCS Service Endpoint (`ontology/spcs/`)

A lightweight Python FastAPI container that exposes the RAI graph as a REST API:

```
ontology/spcs/
├── Dockerfile
├── service-spec.yaml
├── app/
│   ├── main.py          # FastAPI app
│   ├── routes/
│   │   ├── nodes.py     # GET /nodes, GET /nodes/{id}, GET /nodes/{id}/neighbors
│   │   ├── edges.py     # GET /edges, GET /edges/path/{from}/{to}
│   │   ├── query.py     # POST /query (Rel query passthrough)
│   │   ├── health.py    # GET /health
│   │   └── scores.py    # GET /governance-scores
│   └── rai_client.py    # RAI SDK wrapper
└── requirements.txt
```

Service spec: public endpoint, readiness probe on `/health`, 2Gi memory.

### Step 7: Sharing Configuration (`sql/15_ontology_sharing.sql`)

1. **Snowflake Share** for the underlying graph data:
   ```sql
   CREATE SHARE ONTOLOGY_GRAPH_DATA_SHARE;
   -- Grant node/edge tables + scores + recommendations as secure views
   ```
2. **SPCS Service Role Grant** for endpoint access:
   ```sql
   GRANT SERVICE ROLE ontology_graph_service!ALL_ENDPOINTS_USAGE
     TO ROLE ONTOLOGY_CONSUMER;
   ```
3. **Internal Listing** — register the ontology graph as a data product in `DATA_PRODUCT_CATALOG` with sample queries
4. **Consumer documentation** — how to query the REST API and what the node/edge schema means

### Step 8: Streamlit Knowledge Graph Page (`ontology/streamlit/pages/6_Knowledge_Graph.py`)

Interactive page using `streamlit-agraph` or `pyvis` to render the graph:
- Filter by layer (METADATA / BUSINESS / both)
- Filter by source system
- Click node → show properties + neighbors
- Governance score heatmap overlay
- RAI recommendation panel (unresolved gaps)
