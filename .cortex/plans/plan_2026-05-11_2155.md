# DCIM (Data Center Infrastructure Management) Demo — Implementation Plan

## Context

Explored the existing project to understand all conventions:
- **Industry demos** live at `industry-demos/<name>/` (not `demos/`)
- **HCLS demo** is the gold reference: README + 10 markdown docs + 10 SQL scripts + 3 data generators + Streamlit page + deploy scripts
- **Fintech demo** is a lighter reference: README + 5 docs + 3 SQL scripts + 1 generator
- **Data generators** import `SourceSystemGenerator` from `tools/data_generator.py` via relative path
- **SQL scripts** use stored procedures writing to `DCA_DEMO.GOVERNANCE.ONTOLOGY_GRAPH_NODES/EDGES`
- **Node IDs** follow pattern: `PREFIX_{MD5(natural_key)}` (e.g., `HCLS_ENC_`, `WD_WKR_`, `PYR_PLAN_`)
- **Raw layer** uses `_IS_CURRENT`, `_LOADED_AT`, `_SOURCE_SYSTEM` (SCD Type 2)
- **Curated layer** uses Dynamic Tables filtering `WHERE "_IS_CURRENT" = TRUE`
- **Your spec requests SCD Type 6** (hybrid: current + historical + original columns)

## Implementation Steps

### Phase 1: Data Generators (3 files)

**1. `industry-demos/dcim/tools/generate_servicenow_data.py`** (~800 lines)
- Generates: `data_centers` (20), `halls` (100), `racks` (2000), `switches` (8000), `ports` (64000), `incidents` (5000), `change_requests` (3000)
- SCD6 columns per record: `current_<attr>`, `historical_<attr>`, `original_<attr>`, `_VALID_FROM`, `_VALID_TO`, `_IS_CURRENT`, `_VERSION`
- Simulates asset movements (switch moved between racks), firmware upgrades, SLA changes

**2. `industry-demos/dcim/tools/generate_workday_dcim_data.py`** (~600 lines)
- Generates: `technicians` (500), `certifications` (3000), `shifts` (50000), `skill_assignments` (2000), `teams` (50)
- SCD6 pattern: tracks certification status changes (Active→Expired), skill upgrades, team reassignments
- Deterministic `uuid5` linkage to ServiceNow via `campus_id` and `technician_id`

**3. `industry-demos/dcim/tools/generate_telemetry_data.py`** (~500 lines)
- Generates: `port_metrics` (500000), `switch_health` (100000), `environmental_sensors` (50000), `alerts` (10000)
- Time-series data (5-minute intervals, 7 days) — NOT SCD6 (telemetry is append-only)
- CRC errors, packet loss, temperature, humidity, power draw
- Links to ServiceNow switches/ports via deterministic IDs

### Phase 2: SQL Scripts (10 files)

**4. `industry-demos/dcim/sql/01_dcim_schemas.sql`**
- Creates `RAW_DEV.SERVICENOW`, `RAW_DEV.WORKDAY_DCIM`, `RAW_DEV.TELEMETRY` schemas
- Grants to DATA_ENGINEER, DATA_STEWARD
- Stage paths: `@RAW_DEV.STAGING.DATA_STAGE/servicenow/`, `/workday_dcim/`, `/telemetry/`

**5. `industry-demos/dcim/sql/02_dcim_load_data.sql`**
- `SP_LOAD_DCIM_DATA()` — schema inference + COPY INTO for all three systems
- Validates SCD6 column presence on ServiceNow/Workday tables

**6. `industry-demos/dcim/sql/03_dcim_curated_layer.sql`**
- Dynamic Tables in `CURATED_DEV.SERVICENOW`, `CURATED_DEV.WORKDAY_DCIM`, `CURATED_DEV.TELEMETRY`
- ServiceNow: `DIM_DATA_CENTER`, `DIM_HALL`, `DIM_RACK`, `DIM_SWITCH`, `FACT_INCIDENTS`, `FACT_CHANGE_REQUESTS`
- Workday: `DIM_TECHNICIAN`, `DIM_CERTIFICATION`, `FACT_SHIFTS`, `FACT_SKILL_ASSIGNMENTS`
- Telemetry: `FACT_PORT_METRICS`, `FACT_SWITCH_HEALTH`, `FACT_ENVIRONMENTAL` (1-minute lag)
- Filters `WHERE "_IS_CURRENT" = TRUE` for dimension tables; retains SCD6 history columns for time-travel queries

**7. `industry-demos/dcim/sql/04_dcim_graph_populate.sql`**
- `SP_DCIM_POPULATE_INFRASTRUCTURE_GRAPH()` — MERGE into ONTOLOGY_GRAPH_NODES/EDGES
- **Nodes**: DATA_CENTER (`DC_DC_`), HALL (`DC_HALL_`), RACK (`DC_RACK_`), SWITCH (`DC_SW_`), PORT (`DC_PORT_`), INCIDENT (`DC_INC_`), TECHNICIAN (`DC_TECH_`), CERTIFICATION (`DC_CERT_`)
- **Edges**: SWITCH_LIVES_IN_RACK, PORT_CONNECTED_TO, INCIDENT_AFFECTS, RACK_IN_HALL, HALL_IN_DC

**8. `industry-demos/dcim/sql/05_dcim_workday_populate.sql`**
- `SP_DCIM_POPULATE_WORKDAY_GRAPH()` — technicians, certs, team assignments
- **Edges**: TECHNICIAN_HAS_CERTIFICATION, TECHNICIAN_ASSIGNED_TO_INCIDENT, TECH_ON_SHIFT, TECH_IN_TEAM

**9. `industry-demos/dcim/sql/06_dcim_risk_scoring.sql`**
- `SP_DCIM_RISK_SCORING()` — the "Critical Maintenance Gap" logic:
  - Switch error_rate > 2% AND assigned technician cert expired → HIGH_RISK node
  - Creates `HCLS_DCIM_RISK_SCORES` analytics table
  - Weighted risk formula: `error_rate_weight * 0.4 + cert_gap_weight * 0.3 + sla_weight * 0.3`
- `SP_DCIM_MTTR_ANALYSIS()` — Mean Time To Repair with staff availability correlation

**10. `industry-demos/dcim/sql/07_dcim_rai_inference.sql`**
- Graph traversal rules for "nearest qualified technician"
- Pathfinding: INCIDENT → SWITCH → RACK → HALL → CAMPUS ← TECHNICIAN (on-shift + certified)
- Entity resolution across ServiceNow location and Workday campus assignment

**11. `industry-demos/dcim/sql/08_dcim_scd6_time_travel.sql`**
- `SP_DCIM_TIME_TRAVEL(p_timestamp TIMESTAMP)` — reconstructs rack/switch state at any point
- Uses SCD6 `historical_*` and `original_*` columns for before/after comparisons
- Creates `DCIM_HISTORICAL_SNAPSHOTS` table for the time-slider UI

**12. `industry-demos/dcim/sql/09_dcim_run_all.sql`**
- `SP_DCIM_MASTER_ORCHESTRATOR()` — runs all procedures in dependency order with timing/error handling
- `SP_DCIM_QUICK_REFRESH()` — lightweight refresh (skip historical recomputation)

**13. `industry-demos/dcim/sql/10_dcim_semantic_views.sql`**
- Semantic Views for Cortex Analyst:
  - `System_Uptime_vs_Staff_Availability` — correlates switch health with technician shift coverage
  - `Risk_Weighted_MTTR` — MTTR adjusted by SLA tier and certification freshness
  - `Port_Health_by_Business_Priority` — telemetry filtered by ServiceNow client SLA tier
