# Snowflake Horizon Ontology + RelationalAI (SPCS) Enhancement Plan

## Context & Key Findings

The existing demo has a strong governance foundation (14 tags, 8 masking policies, role hierarchy, contracts, DMFs) but stops short of Horizon's advanced capabilities. The `ontology/` folder already establishes the philosophical framework — "every Snowflake object that carries institutional meaning is a materialised human agreement." The gap is operationalising this with:

1. **Horizon's self-reinforcing governance loop** (classify → tag → protect → propagate → monitor → audit)
2. **RelationalAI as the reasoning engine** that discovers, validates, and extends the ontology through graph intelligence

---

```
┌─────────────────────────────────────────────────────────────────┐
```

RAI acts as the "governance brain" — it reasons over the metadata graph to discover what Horizon should enforce, while Horizon is the enforcement engine.

## Implementation Steps

### Phase 1: Elevate Horizon Governance (sql/11_horizon_advanced.sql)

1. **Auto-Classification** — Use `SYSTEM$CLASSIFY()` with `auto_tag: true` to discover PII automatically (replaces manual column-by-column tagging)
2. **Tag-Based Masking** — Migrate from column-level policy attachment to `ALTER TAG ... SET MASKING POLICY` so any future tagged column is automatically protected
3. **Tag Propagation** — Enable `PROPAGATE = ON_DEPENDENCY_AND_DATA_MOVEMENT` on classification tags so protection flows through Dynamic Tables and CTAS
4. **Lineage Queries** — Build views over `SNOWFLAKE.ACCOUNT_USAGE.ACCESS_HISTORY` and `TAG_REFERENCES_WITH_LINEAGE` to show tag flow
5. **Trust Center Integration** — Create scanner configuration for governance posture monitoring
6. **Conditional Tag-Value Masking** — Single masking policy that reads `SYSTEM$GET_TAG_ON_CURRENT_COLUMN()` to apply different masks per classification level

### Phase 2: RelationalAI Knowledge Graph (sql/12_relationalai_setup.sql + python/rai_models/)

1. **SPCS Setup** — Install RAI Native App from Marketplace, configure compute pool, create engine
2. **Metadata Graph Model** — Stream `INFORMATION_SCHEMA.TABLES`, `COLUMNS`, `TAG_REFERENCES`, `DATA_PRODUCT_CATALOG`, role grants into a RAI model that represents the full platform ontology as a knowledge graph
3. **Entity Resolution** — Use graph algorithms (WCC, Jaccard similarity) to detect duplicate/conflicting business entities across source systems (the "revenue" gap from Module 4)
4. **Governance Gap Detection** — Declarative rules that identify: untagged PII candidates, orphaned tables, broken lineage paths, over-privileged roles, ungoverned data products
5. **Ontology Reasoning** — Rules that infer classifications: "if a column receives data from a PII-tagged upstream column via lineage, it should also be classified"
6. **Relationship Discovery** — Graph analysis that discovers undocumented FK relationships between tables, enhancing Semantic View accuracy
7. **Export as Stored Procedures** — RAI results write back to Snowflake tables for Horizon to consume (e.g., `GOVERNANCE.RAI_RECOMMENDATIONS`)

### Phase 3: Integration Layer (sql/13_rai_horizon_bridge.sql)

1. **RAI → Horizon Feedback Loop** — Stored procedure that reads RAI recommendations and applies tags/policies via `ALTER TABLE ... SET TAG`
2. **Governance Scorecard** — RAI computes a composite governance health score per data product using graph centrality + coverage metrics
3. **GraphRAG for Cortex Analyst** — RAI knowledge verbalization feeds Cortex Analyst with ontology context, improving NL query accuracy for governance questions

### Phase 4: Streamlit Enhancements (streamlit/ pages)

1. **Ontology Graph Visualizer** — Interactive network graph (pyvis/plotly) showing tables → tags → policies → roles as a knowledge graph
2. **RAI Governance Recommendations** — Page showing RAI-discovered gaps with one-click remediation
3. **Lineage Explorer** — Tag propagation visualization through the medallion layers
4. **Entity Resolution Report** — Show conflicting definitions discovered by RAI (e.g., the "revenue" semantic gap)

### Phase 5: Demo Script Enhancement (docs/DEMO_SCRIPT_HORIZON_RAI.md)

A new ~20-minute demo flow:
1. **"Classify Everything"** — Run `SYSTEM$CLASSIFY` live, watch tags auto-apply
2. **"Protect Once, Enforce Everywhere"** — Show tag-based masking auto-protecting new columns
3. **"The Governance Brain"** — RAI surfaces that `CURATED.CUSTOMER_PII_EXTRACT` has unmasked PII flowing from a tagged source
4. **"Resolve Conflicts"** — RAI entity resolution detects the Sales vs Finance revenue conflict
5. **"Self-Healing Ontology"** — RAI recommendation → Horizon enforcement → propagation through lineage
6. **"Ask the Graph"** — Cortex Analyst answers "which data products are at governance risk?" using GraphRAG
